# EVERBLOOM — Living village implementation and acceptance

**Lane:** Village Engineer. Original authored dialogue, locations, four festivals and six NPC work/leisure/rest patterns are in `data/village_life.json`; the existing six resident identities and original primitive representations remain in `data/villagers.json` and `scripts/village.gd`.

## Implemented, not aspirational
- Six distinct residents have deterministic hourly routes: home, village square, workplace, lunch break, individual weekly rest day, leisure site and rain shelter. They move toward destinations at a fixed 2.4-world-unit/second speed during actual play; deterministic `sync_schedule(true)` snaps test fixtures and load/day transitions. This is direct linear steering, **not** pathfinding, crowd avoidance, navigation meshes, animation or collision-aware traversal.
- All four seasons have original, resident-specific lines. Work, rain, friendship and festival contexts change spoken lines; each resident has a persistent talk/gift/job/festival memory. Friendship tiers reflect existing affection thresholds but do **not** implement dating, marriage or children.
- Favorite gifts grant 18 friendship; other accepted preferred gifts grant 12. A resident can receive one gift and one rewarded talk per monotonic day. No gifts or friendship rewards are duplicated on same-day reload. **V03/V06 increment:** each of six residents now has distinct original favorite/preferred gift recollection dialogue, voiced through the existing talk action on a later monotonic day. The reaction is consumed once per gifted epoch (not once per save load) and grants no additional affection, currency, restoration or items. Festival and rain dialogue take precedence; the recollection remains pending until a clear non-festival conversation. This is authored text/UI feedback, not synthesized voice or finished cinematics.
- `village.act("job", position)` runs a genuine paid village shift for one employer/day, if physically near the NPC at work, between 09:00–16:00 (except 12:00–13:00), not on their weekly rest day or at a festival. A shift spends 12 energy, earns 24 petals and grants one restoration point. It is persisted and idempotent across reloads. **The `K` keyboard shortcut is integrated on main by Principal**, but controller/touch parity and manual gameplay usability remain unverified.
- Original festivals: Seed Lantern Walk (Spring 7), Lake of Stars (Summer 11), The Hearth Table (Autumn 9), Frostglass Bells (Winter 12), 17:00–22:00. NPCs gather at the village square. A player who talks to a villager during a festival attends once per festival/year and earns a small one-time friendship/restoration reward. Festival attendance is available through the existing talk tool and persists across saves.
- Existing schema-1 `village` save fields `affection`, `talked`, `gifted` remain. New optional `worked`, `festivals`, `memories` fields have defaults, bounds and deep-copy snapshots; old saves still load. New optional per-resident memory keys `last_gift_favorite` (bool), `recalled_gift_epoch` (monotonic integer, -1 when absent), and `gift_recollections` (0..1,000,000) roundtrip through the existing schema-1 memory dictionary. Old saves infer favorite status from the original resident catalog. Principal should explicitly validate these keys in its central save validator before treating malformed external payloads as fully covered.

## Verification and remaining scope
The independent `scripts/village_life_acceptance.gd` exercises the actual `scripts/village.gd` in native Godot: deterministic 56-day × 5-time-slot × 6-resident schedules, work payments, energy debits, rest days, favorite gifts, duplicate rejection, save JSON roundtrip, year-two festivals and seasonal dialogue. Workflow `.github/workflows/everbloom-village-life-acceptance.yml` pins Godot 4.7.2 and its SHA-256, with no Codex. **Native proof must be attached only after exact-head CI passes.**

Unimplemented: real pathfinding and dynamic obstacles; a polished job selection UI and tutorial; deeper personality/reputation simulation, romance/marriage/family, pregnancy/children, multiple authored homes/interiors, festival minigames and visual/audio art, actual controller/mobile/performance tests, 20+ NPC target, quest branching and full narrative chapters. The event schedule is a functional foundation, not a finished village.

## V03/V06 gift-recollection contract (2026-11-02)

- **Player verb and feedback:** Give a preferred item with the existing gift action, then speak with the same NPC on a later day; one resident-specific line references the actual item and its favorite/preferred context. Dialogue is visible in the existing text HUD; no new input mapping or resource reward is introduced.
- **Determinism:** The trigger uses `game.day_epoch()` (56 days/year), not season/day alone. The saved `recalled_gift_epoch` prevents replay after a reload or year rollover. Festival/rain context has precedence, and an unrecalled older gift is replaced by a new gift without duplicating resources.
- **Dependencies:** Village owns dialogue and nested memory; Principal owns save validation, input, and HUD. This branch does not change central save shape or other domain contracts. Central validator currently accepts safe extra nested keys; strict validation for new keys is a Principal handoff.
- **Original asset plan:** Six resident-specific text pairs are authored in `data/village_life.json`; future facial animation and voiced performances require independently created/licensed assets and accessibility captions. Existing capsule avatars remain placeholders.
- **Controls and accessibility:** Uses existing keyboard talk/gift actions; gamepad/touch input and focus are **not verified**. Text lines use existing HUD feedback; a scrollable dialogue history and localization keys remain future V05/V19 work.
- **Performance budget:** O(1) memory check per talk; no per-frame extra work or new scene nodes. Actual frame time, memory usage and mobile performance have **not** been measured.
- **Acceptance:** Native Godot village runner checks delayed recollection, exactly-once dialogue, JSON roundtrip, legacy save fallback, favorite vs preferred text, year-4-to-5 continuity and unchanged inventory conservation. Exact-head CI proof must be recorded separately; source changes alone do not constitute a native pass.
- **Status:** V03 and V06 **implementing** (bounded gift-memory slice only); V01/V02/V07/V09 have earlier partial native-tested foundations. Neither mission is fully complete; family/romance/restoration arcs and complete localization remain future work.
