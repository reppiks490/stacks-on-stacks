# EVERBLOOM — Living village implementation and acceptance

**Lane:** Village Engineer. Original authored dialogue, locations, four festivals and six NPC work/leisure/rest patterns are in `data/village_life.json`; the existing six resident identities and original primitive representations remain in `data/villagers.json` and `scripts/village.gd`.

## Implemented, not aspirational
- Six distinct residents have deterministic hourly routes: home, village square, workplace, lunch break, individual weekly rest day, leisure site and rain shelter. They move toward destinations at a fixed 2.4-world-unit/second speed during actual play; deterministic `sync_schedule(true)` snaps test fixtures and load/day transitions. This is direct linear steering, **not** pathfinding, crowd avoidance, navigation meshes, animation or collision-aware traversal.
- All four seasons have original, resident-specific lines. Work, rain, friendship and festival contexts change spoken lines; each resident has a persistent talk/gift/job/festival memory. Friendship tiers reflect existing affection thresholds but do **not** implement dating, marriage or children.
- Favorite gifts grant 18 friendship; other accepted preferred gifts grant 12. A resident can receive one gift and one rewarded talk per monotonic day. No gifts or friendship rewards are duplicated on same-day reload. **V03/V06 increment:** each of six residents now has distinct original favorite/preferred gift recollection dialogue, voiced through the existing talk action on a later monotonic day. The reaction is consumed once per latest gift, with the actual later conversation epoch persisted (not once per save load) and grants no additional affection, currency, restoration or items. Festival and rain dialogue take precedence; the recollection remains pending until a clear non-festival conversation. This is authored text/UI feedback, not synthesized voice or finished cinematics.
- `village.act("job", position)` runs a genuine paid village shift for one employer/day, if physically near the NPC at work, between 09:00–16:00 (except 12:00–13:00), not on their weekly rest day or at a festival. A shift spends 12 energy, earns 24 petals and grants one restoration point. It is persisted and idempotent across reloads. **The `K` keyboard shortcut is integrated on main by Principal**, but controller/touch parity and manual gameplay usability remain unverified.
- Original festivals: Seed Lantern Walk (Spring 7), Lake of Stars (Summer 11), The Hearth Table (Autumn 9), Frostglass Bells (Winter 12), 17:00–22:00. NPCs gather at the village square. A player who talks to a villager during a festival attends once per festival/year and earns a small one-time friendship/restoration reward. Festival attendance is available through the existing talk tool and persists across saves.
- Existing schema-1 `village` save fields `affection`, `talked`, `gifted` remain. New optional `worked`, `festivals`, `memories` fields have defaults, bounds and deep-copy snapshots; old saves still load. New optional per-resident memory keys `last_gift_favorite` (bool), `recalled_gift_epoch` (monotonic integer, -1 when absent), and `gift_recollections` (0..1,000,000) roundtrip through the existing schema-1 memory dictionary. Old saves infer favorite status from the original resident catalog. Principal should explicitly validate these keys in its central save validator before treating malformed external payloads as fully covered.

## V03/V06/V20 gift recollection chronology repair (2026-11-02)

- **Confirmed contract mismatch:** Previous Village code saved `recalled_gift_epoch` as the original gift epoch, but Principal's strict schema-1 admission accepts only -1 or a recollection epoch **on/after** `last_gift_epoch`. The Village loader also truncated a later recollection day back to the gift day. A later gift could therefore make a legitimate Village snapshot fail central admission.
- **Player interaction and feedback:** Give a preferred/favorite item, talk on a later clear non-festival day to hear the authored resident recollection, then give another gift (including after talking on the same day). The second gift remains eligible for a future recollection. Rain/festival dialogue still defers this reaction; no additional reward is minted by a recollection.
- **Authoritative state:** `last_gift_epoch` remains the original monotonic gift day; `recalled_gift_epoch` now means the actual later day the NPC recalled that latest gift, or -1 while pending. Giving a new gift resets only the pending marker, **not** lifetime `gift_recollections`. Loading an admitted snapshot preserves a later recalled day up to `game.day_epoch()` without truncating to the gift date. The 56-day/year calendar and existing schema-1 keys are unchanged.
- **Legacy limitation and Principal handoff:** Old snapshots with a recollection keyed to an earlier gift and then a newer unrecalled gift can contain `0 <= recalled_gift_epoch < last_gift_epoch`. Current Principal admission rejects these **before** Village loads them. A coordinated, explicitly versioned pre-admission migration is required to recover those historical states; this Village-only repair does not claim to have implemented such a migration or changed Principal-owned files. Old single-gift records where recollection equals gift day remain treated as already consumed, preserving prior behavior.
- **Native regression:** Existing village-life suite now checks day-2 and year-five actual recollection epochs. Added a separate 224→225→226→227→228 scenario covering year rollover, talk-then-gift same day, a second gift and JSON reload, deferred rainy-day recollection, no duplicate dialogue, conserved petals and exactly three consumed flowers. Run pinned Godot 4.7.2 village-life acceptance, calendar, journal and general native CI at the exact branch HEAD; do not infer a pass from source inspection.
- **Dependencies and original asset plan:** Village owns `village.gd`/native village acceptance and first-party authored text; Principal owns `SaveService`, assembled save migrations and UI input. Builder/Emergence catalogs are untouched. Existing original capsule NPCs/HUD display lines; later independently authored facial animation/captions are optional. No external/proprietary assets added.
- **Controls/performance/status:** Uses existing gift/talk keyboard controls and journal; physical controller/touch/mobile accessibility remain unverified. O(1) gift and recollection updates, no new per-frame work or save keys; no measured device frame-time/memory. **V03/V06/V20 remain partial**, pending native exact-SHA CI and Principal's old-save migration/assembled-game verification.
