## Real player interaction and state semantics
Existing thirty-bed till/plant/harvest/water controls, procedural wet-soil feedback and crop season rules are preserved. The new `Farm.attach_water_network(network)` is explicitly opt-in. When a same-day conserved network is attached, the existing `Farm.act("water", position)` player verb requests exactly 20 finite units for the nearest bed. The network debits 20, delivers 18 and records two units as channel loss. Soil gains the **delivered** amount, not an unlimited refill to 100. HUD-compatible text reports delivery and loss. Failed water, daily duplicates and stale network state do not spend energy. If the game rejects the one-energy charge after withdrawal, the exact network snapshot is restored before any soil change. When no network is attached, the preexisting watering-can behavior remains unchanged, so canonical gameplay does not silently change before save integration.

Soil daily transition uses the original pure F02 per-bed hydrology adapter. For each of thirty beds: `moisture_before + rainfall = runoff + drainage + evaporation + moisture_after`. Catchment intake must be **exactly** the sum of soil runoff, never all rainfall or already-retained moisture. Reservoir invariant: `initial + captured_inflow = stored + spilled + evaporated + delivered + channel_loss`. Two separate finite ledgers are checked in the native combined runner; one input cannot be credited twice. Calendar is `(year - 1) * 56 + season_index * 14 + day` and reservoir rejects repeated/skipped days.
