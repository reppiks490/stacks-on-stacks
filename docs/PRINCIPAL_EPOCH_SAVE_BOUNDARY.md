# Principal P02/P04/P05 — saved monotonic daily-action epoch integrity

**Scope:** bounded hardening of existing Godot 4.x save schema-1, not a new gameplay feature or a change to any Farming/Village domain-owned script. Branch `game/everbloom-principal-epoch-save-20261102` based on `main@593c0296a94549119b4b5ad93149be7f31a9eb68`. Exact final commit and native CI results must be recorded in issue #2 separately.

## Defect and player impact

The assembled game persists 56 days/year (`(year-1)*56+season*14+day`). Before this change, SaveService accepted any JSON-safe nonnegative integer for `farm[].last_harvest_epoch`, `animals.<id>.last_care` and `village.talked/gifted/worked.<id>`, even when that date lay in the future relative to the saved calendar. Farm, Animals and Village `load_state()` then silently clamped those impossible values to the current epoch. This breaks the promise that accepted save snapshots roundtrip without changed action history and can incorrectly mark current-day actions already performed. No new resources or rewards are generated by this patch.

## Authority contract

- Calendar authority remains `scripts/game.gd::day_epoch()`; the save boundary computes the identical monotonic epoch from validated year/season/day before loading any domain.
- Optional pre-year schema-1 snapshots continue to use year 1. `MAX_SAFE_YEAR=160842843834660` ensures even the last day of the 56-day year is within JSON's exact 2^53-1 integer range.
- Each present daily-action epoch must be an integral number from -1 (never performed) through the saved epoch, inclusive. The same bound is used for existing Village gift-recollection chronology. Legacy missing optional fields remain accepted.
- Invalid future/fractional/negative epoch values reject the entire snapshot **before** mutating player currency, inventory, relationships, crop beds or animals. No attempt to auto-correct the saved history is allowed.
- Player verbs remain existing farm harvest, animal care, Village talk/gift/paid shift; UI messages, keyboard interaction, save and load are unchanged. Touch/controller and performance remain unverified, not inferred.
- Runtime cost: O(number of saved crop beds + animals + Village ledger entries) during validation only; no per-frame work, no new assets, no added storage, no external dependencies. Existing original art provenance unchanged.

## Regression and limitations

`scripts/principal_save_acceptance.gd` adds native Godot rollover cases for year 1 day 56 versus year 2 day 57, all five daily-action categories, exact-safe-year upper bound, and assembled-game failed-write byte conservation. Full cross-loop QA and non-Codex native CI at the exact final commit are required before integration.

**Separate preexisting clock defect, deferred to Principal `game.gd` change:** `SaveService` currently accepts minute values 0–1440, while `game.load_game()` clamps to 360–1319. Rejecting late-evening saves solely in the validator would regress playable save behavior. Correct this with a coordinated runtime/load policy and regression tests rather than silently tightening the validator here.

**Not claimed:** Windows file locking, cross-process locking, fsync/power-loss durability, v2 migration, measured mobile input/performance, or completion of P02/P04/P05. Innovation Phase C remains closed until a joint 220-concept semantic/feasibility audit.
