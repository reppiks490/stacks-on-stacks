# EVERBLOOM V02/V07 — Physical commute employment admission

**Status:** implementing; isolated candidate until exact-HEAD native acceptance and reconciliation. Godot 4.x baseline only. Mission IDs V02, V07, V20.

## Player-visible defect and correction
Village residents follow deterministic daily destinations, but `sync_schedule(false, delta)` immediately updates each resident's destination label while the actual actor walks at 2.4 world units/second. Previously `village.act("job", ...)` trusted that label, permitting a player near the commuting actor to earn a full paid shift before the actor reached the workplace. The Village job authority now additionally requires the actor to be within **1.0 world unit of the actual authored workplace** in world coordinates. A rejected attempt returns “is still on their way to work. Meet them at the workplace.” The existing HUD and work button display the message; keyboard K, mouse/touch button and controller X continue to dispatch the same Village authority.

## State, economics and dependency contracts
The arrival check occurs **before** the energy debit, petals credit, restoration grant and job memory write. A rejection must preserve money, energy, restoration, social state and inventory. Existing shift hours, lunch exclusion, weekly rest days, festival restrictions and once-per-monotonic-day idempotence remain authoritative. No new save fields, scene nodes, item recipes, asset dependencies or shared input contracts. `day_epoch=(year-1)*56+season_index*14+day` remains Principal-owned. The worksite is transformed from Village-local coordinates into world space so moving the Village scene root cannot bypass admission. Principal retains `game.gd`, save admission, HUD and global controls; Farming, Construction and Emergence paths are untouched.

## Deterministic native acceptance
`scripts/village_schedule_acceptance.gd` executes the real Village code and original six-resident catalog in Godot, not a Python mock. It sweeps 112 days (two 56-day years), eight time slots per day and rainy/clear days, checks authored destinations and snap coordinates, and tests a genuine in-transit worker, a partially progressed commute, arrival, one paid shift, repeat rejection, JSON reload, year-two new work epoch and lunch refusal. The dedicated push-only, checksum-pinned Godot workflow is `.github/workflows/everbloom-v02-commute.yml`. Exact-SHA logs must be inspected before claiming native PASS or integration. Other Village/QA workflows must remain green.

## Visuals, controls, performance and limitations
The current residents are first-party capsule primitives with original authored schedule positions. No third-party models, voice, textures or copied game assets. Future original walk cycles, navmesh paths, collision avoidance and village renovation-aware routing require Builder/Principal contracts. This is **arrival gating, not pathfinding**: straight-line movement may cross obstacles, crowd collisions are not simulated and the native fixture uses synthetic time/input, not physical controllers. The added job admission check is one Vector3 distance computation per attempted shift, not per-frame. No measured desktop/mobile frame time, memory, touch ergonomics or accessibility-device proof is claimed. Schedule validity is for current authored static destinations; dynamic blocked paths are not solved.
